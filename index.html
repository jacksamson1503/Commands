📜 S3 Bucket Policies (JSON Templates) ▼
Policy NameJSON
Public Read Access
Allow anyone to read objects		 
{
  "Version": "2012-10-17",
  "Statement": [{
    "Sid": "PublicReadGetObject",
    "Principal": "*",
    "Effect": "Allow",
    "Action": ["s3:GetObject"],
    "Resource": ["arn:aws:s3:::your-bucket-name/*"]
  }]
}
Restrict to Specific IP
Only your IP can access		 
{
  "Version": "2012-10-17",
  "Statement": [{
    "Sid": "AllowOnlyMyIP",
    "Effect": "Allow",
    "Principal": "*",
    "Action": "s3:GetObject",
    "Resource": "arn:aws:s3:::your-bucket-name/*",
    "Condition": {
      "IpAddress": {
        "aws:SourceIp": "YOUR_IP/32"
      }
    }
  }]
}
Force HTTPS Only
Deny all HTTP access		 
{
  "Version": "2012-10-17",
  "Statement": [{
    "Sid": "DenyNonHTTPS",
    "Effect": "Deny",
    "Principal": "*",
    "Action": "s3:*",
    "Resource": [
      "arn:aws:s3:::your-bucket-name",
      "arn:aws:s3:::your-bucket-name/*"
    ],
    "Condition": {
      "Bool": {
        "aws:SecureTransport": "false"
      }
    }
  }]
}

sudo tee /etc/systemd/system/prometheus.service <<EOF
[Unit]

☁️ Cloud Computing Theory ▼
ConceptTheory & Use Case
Cloud ComputingInternet-based compute, storage, networking, database, and managed services. Use it to launch faster, scale on demand, and pay for actual usage.
IaaSVirtual machines, disks, networks, and firewalls. Use case: EC2 Linux server with full OS control.

Private CloudDedicated cloud for one organization. Use case: banking, government, strict compliance workloads.
Hybrid CloudOn-premises plus public cloud. Use case: database on-premises, app and analytics in AWS.
Region / AZRegion is geography; AZ is isolated data center area. Use case: deploy across two AZs for high availability.
ScalabilityHandle more load by adding resources. Use case: add EC2 instances during peak traffic.
ElasticityScale up and down automatically. Use case: Auto Scaling adds capacity at peak and saves cost at night.
High AvailabilitySystem stays running during component failure. Use case: ALB plus EC2 in multiple AZs.
Disaster RecoveryRestore service after major outage. Use case: backups, snapshots, cross-region replication, RTO/RPO.
Shared ResponsibilityAWS secures cloud infrastructure; customer secures IAM, data, OS, network rules, and app configuration.

🎯 Linux Interview Q&A Tips ▼
QuestionStrong Answer / Use Case
CPU and memory?Use top, htop, free -h, vmstat. Check load, memory pressure, top processes.
Disk usage?Use df -h and du -sh *. Find which filesystem/folder filled the server.
Check logs?Use journalctl, tail -f, grep ERROR. Match logs with deployment/change time.
Service down?Check systemctl status, logs, listening port, config, disk, memory, recent deploy.
Permission denied?Check owner, group, mode, parent permission. Use ls -l, chmod, chown.
High CPU?Find PID with top/ps, inspect logs/thread dump, restart only after impact check.
Network issue?Use ping, curl -v, nc, traceroute, dig. Check DNS, port, route, firewall.
Soft vs hard link?Hard link points to inode; soft link points to path and can break if target moves.
