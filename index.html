📜 S3 Bucket Policies (JSON Templates) ▼
Policy NameJSON
Public Read Access
Allow anyone to read objects		 
{
  "Version": "2012-10-17",
  "Statement": [{
    "Sid": "PublicReadGetObject",
    "Principal": "*",
    "Effect": "Allow",
    "Action": ["s3:GetObject"],
    "Resource": ["arn:aws:s3:::your-bucket-name/*"]
  }]
}
Restrict to Specific IP
Only your IP can access		 
{
  "Version": "2012-10-17",
  "Statement": [{
    "Sid": "AllowOnlyMyIP",
    "Effect": "Allow",
    "Principal": "*",
    "Action": "s3:GetObject",
    "Resource": "arn:aws:s3:::your-bucket-name/*",
    "Condition": {
      "IpAddress": {
        "aws:SourceIp": "YOUR_IP/32"
      }
    }
  }]
}
Force HTTPS Only
Deny all HTTP access		 
{
  "Version": "2012-10-17",
  "Statement": [{
    "Sid": "DenyNonHTTPS",
    "Effect": "Deny",
    "Principal": "*",
    "Action": "s3:*",
    "Resource": [
      "arn:aws:s3:::your-bucket-name",
      "arn:aws:s3:::your-bucket-name/*"
    ],
    "Condition": {
      "Bool": {
        "aws:SecureTransport": "false"
      }
    }
  }]
}

sudo tee /etc/systemd/system/prometheus.service <<EOF
[Unit]

Cloud, DevOps Theory & Use Cases

7 sections
☁️ Cloud Computing Theory ▼
ConceptTheory & Use Case
Cloud ComputingUsing internet-based compute, storage, networking, database, security, and managed services instead of buying physical servers. Use it to launch applications faster, scale during traffic, and pay only for what you use.
IaaSInfrastructure as a Service gives virtual machines, disks, networks, and firewalls. Use case: run a custom Linux server on EC2 when you need full OS control.
PaaSPlatform as a Service manages runtime, scaling, and deployment platform. Use case: deploy code without managing the base server, patching, or capacity planning.
SaaSSoftware as a Service is ready-made software accessed through browser/API. Use case: GitHub, Jira, Gmail, Datadog, and other tools consumed directly by teams.
Public CloudProvider-owned infrastructure shared securely by many customers. Use case: quickly launch workloads across regions.
Private CloudCloud-like platform dedicated to one organization. Use case: banking, government, or regulated systems needing stricter control.
Hybrid CloudMix of on-premises/private cloud and public cloud. Use case: keep sensitive databases on-premises while running web apps or analytics in AWS.
Multi CloudUsing more than one cloud provider. Use case: avoid vendor lock-in, meet regional requirements, or use the best service from each provider.
RegionGeographic cloud location containing multiple Availability Zones. Use case: deploy close to users for lower latency and data residency.
Availability ZoneSeparate data center zone inside a region. Use case: place app servers across multiple AZs so one data center failure does not stop the app.
ScalabilityAbility to handle more load by adding resources vertically or horizontally. Use case: add EC2 instances during sale traffic.
ElasticityAutomatic scaling up and down based on demand. Use case: Auto Scaling increases capacity at peak hours and reduces cost at night.
High AvailabilityDesigning systems to stay running even when components fail. Use case: Load Balancer plus EC2 instances across two AZs.
Fault ToleranceSystem continues operating after failure. Use case: replicated database, queue retries, backups, and multi-AZ deployment.
Disaster RecoveryPlan to restore service after a major outage. Use case: backups, snapshots, cross-region replication, RTO, and RPO planning.
Shared ResponsibilityProvider secures cloud infrastructure; customer secures data, IAM, network rules, OS patches, and app configuration. Interview point: responsibility changes across IaaS, PaaS, and SaaS.

🧩 AWS Services Theory & Real Use Cases ▼
AWS ServiceTheory & Use Case
EC2Virtual server in AWS. Use case: host a web app, Jenkins server, Docker host, bastion server, or custom Linux workload.
S3Object storage for files, backups, logs, static assets, and artifacts. Use case: store website images, Terraform state, build artifacts, database backups, and static website files.
VPCPrivate network boundary for AWS resources. Use case: create public subnets for load balancers and private subnets for app/database servers.
SubnetSmaller network range inside a VPC and Availability Zone. Use case: separate public, private app, and private database layers.
Internet GatewayAllows public subnet resources to reach the internet. Use case: public ALB or bastion host receives internet traffic.
NAT GatewayAllows private subnet instances to access internet outbound without receiving inbound internet traffic. Use case: private EC2 downloads packages safely.
Route TableControls where subnet traffic goes. Use case: route public subnet traffic to Internet Gateway and private subnet traffic to NAT Gateway.
Security GroupStateful virtual firewall attached to resources. Use case: allow port 443 from internet to ALB and app port only from ALB to EC2.
NACLStateless subnet-level firewall. Use case: add an extra network boundary for compliance or block unwanted CIDR ranges.
IAMIdentity and access management for users, groups, roles, and policies. Use case: give EC2 an IAM role to read S3 without storing access keys on the server.
LambdaServerless function that runs code on events. Use case: process S3 uploads, run scheduled cleanup, handle API Gateway requests, or automate alerts.
RDSManaged relational database service. Use case: run MySQL, PostgreSQL, MariaDB, Oracle, or SQL Server with backups, patching, and Multi-AZ support.
DynamoDBManaged NoSQL key-value/document database. Use case: store session data, user preferences, IoT events, or high-scale application metadata.
EKSManaged Kubernetes control plane. Use case: run containerized microservices with Kubernetes while AWS manages control-plane components.
ECSAWS container orchestration service. Use case: run Docker containers without managing Kubernetes complexity.
ECRPrivate container image registry. Use case: Jenkins builds Docker image, pushes to ECR, then ECS/EKS pulls the image for deployment.
Elastic Load BalancerDistributes traffic across targets. Use case: ALB routes HTTP/HTTPS traffic to multiple EC2 instances or Kubernetes services.
Auto Scaling GroupAutomatically adds/removes EC2 instances based on demand or health. Use case: scale application servers when CPU or request count increases.
CloudWatchMetrics, logs, alarms, and dashboards. Use case: monitor EC2 CPU, Lambda errors, application logs, and trigger alerts when thresholds cross.
CloudTrailRecords AWS API activity for auditing. Use case: find who deleted an S3 bucket policy, changed security groups, or created an IAM user.
Route 53DNS and domain routing service. Use case: point app.example.com to an ALB and use health checks for failover.
CloudFrontContent delivery network for low-latency global access. Use case: cache static website files, images, and APIs near users worldwide.
API GatewayManaged API front door. Use case: expose REST/HTTP APIs backed by Lambda, ECS, EKS, or private services with auth and throttling.
SNSPub/sub notification service. Use case: send alerts to email, SMS, Lambda, or SQS when a CloudWatch alarm fires.
SQSManaged message queue. Use case: decouple services, retry failed work, and handle traffic spikes without losing requests.
EBSBlock storage volume for EC2. Use case: attach persistent disk to a Linux server for application data or database files.
EFSShared file system for Linux workloads. Use case: multiple EC2 instances or containers share uploaded files.
Secrets ManagerStores and rotates secrets. Use case: keep database passwords, API tokens, and credentials out of code and Jenkins variables.
KMSKey management and encryption service. Use case: encrypt S3 objects, EBS volumes, RDS databases, and application secrets.
CloudFormationAWS native Infrastructure as Code. Use case: create VPC, EC2, IAM, and RDS through repeatable templates.
CodePipelineAWS CI/CD orchestration service. Use case: source from Git, build with CodeBuild, deploy to ECS, EC2, Lambda, or S3.

🤖 CI/CD Pipeline Concepts & Theory ▼
ConceptTheory & Use Case
Continuous IntegrationDevelopers merge code frequently and every change is built/tested automatically. Use case: Jenkins runs tests whenever code is pushed to GitHub.
Continuous DeliveryCode is always ready to deploy after automated checks, but production release may need manual approval. Use case: staging deployment auto, production button approval.
Continuous DeploymentEvery successful change automatically reaches production. Use case: mature teams deploy small safe changes many times per day.
Pipeline StagesCommon flow: checkout, install dependencies, unit test, build artifact/image, scan, push artifact, deploy, smoke test, notify.

Pipeline SecretsCredentials used by CI/CD must be stored securely. Use case: Jenkins credentials, GitHub Actions secrets, AWS IAM role, or Secrets Manager.

🎯 Linux Interview Q&A Tips ▼
QuestionStrong Answer / Use Case
How do you check CPU and memory?Use top, htop, free -h, vmstat. Explain that you check current usage, load average, memory pressure, and top processes.
How do you check disk usage?Use df -h for filesystem usage and du -sh * for folder size. Use case: find which folder filled the server disk.
How do you check logs?Use journalctl -u service, tail -f /var/log/syslog, or app log path. Mention filtering errors with grep.
How do you troubleshoot service down?Check systemctl status, logs, port listening with ss -tulpn, config changes, disk, memory, and recent deployments.
Permission denied issue?Check owner, group, mode, parent directory permission, and SELinux/AppArmor if enabled. Commands: ls -l, chmod, chown.
Process is using high CPU?Find PID using top or ps aux --sort=-%cpu, inspect logs, thread dump if Java, and restart only after understanding impact.
How do you check network connectivity?Use ping, curl -v, telnet/nc, traceroute, dig/nslookup. Check DNS, port, route, firewall, and service status.
Hard link vs soft link?Hard link points to same inode and cannot cross filesystems easily; soft link points to path and can break if target is removed. Use case: symlink config paths.
What is load average?Average number of runnable/waiting processes over 1, 5, 15 minutes. Compare with CPU core count to understand pressure.
How do you safely edit production config?Backup file, validate syntax, change with least scope, reload service if supported, watch logs, and keep rollback ready.
